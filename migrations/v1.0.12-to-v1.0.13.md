# Migration Guide: `android-v1.0.12` → `android-v1.0.13`

---

## Deprecations (non-breaking)

### `AstroConnect.preload(configuration, onSuccess, onError)` is deprecated

A new `preload` overload delivers a single terminal result through `onPreloadEnded(reason)` so integrators can distinguish a fully loaded page from a deferred handoff (e.g. when a biometric prompt is shown only after `AstroConnectView` is displayed).

The deprecated overload still works. For backward compatibility, `onSuccess` is now also invoked for the deferred case so existing integrators are not left waiting indefinitely.

```kotlin
// BEFORE (v1.0.12) — still works, but deprecated
AstroConnect.preload(
    configuration = configuration,
    onSuccess = { /* SDK ready */ },
    onError = { error -> /* failed */ },
)

// NOW (v1.0.13)
AstroConnect.preload(
    configuration = configuration,
    onPreloadEnded = { reason ->
        when (reason) {
            is AstroPreloadEndReason.Loaded -> { /* page fully loaded — opens instantly */ }
            is AstroPreloadEndReason.Deferred -> { /* preload ended without full load; biometric or live view will handle the rest */ }
            is AstroPreloadEndReason.Failed -> { /* preload failed: reason.error */ }
        }
    },
)
```

---

## New Features (optional)

### Pre-load load timeout *(since v1.0.13)*

`AstroConnect.preload` now applies the SDK load timeout to the preload phase. If the page neither loads nor errors within the timeout, the callback receives `Failed` (or the legacy `onError`) instead of hanging indefinitely.

### Deferred biometric prompt during preload *(since v1.0.13)*

When the SDK requires biometric authentication to finish loading, the prompt is automatically deferred until `AstroConnectView` is displayed. The user is never prompted before the SDK is on screen.

### Preload configuration mismatch *(since v1.0.13)*

If you call `preload(configuration)` and later open `AstroConnectView` with a different configuration, the previously preloaded session is discarded. Your `onPreloadEnded` callback (or the legacy `onError`) is now invoked with `Failed(InvalidConfiguration)` so it cannot be left hanging.
