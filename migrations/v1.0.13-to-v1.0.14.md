# Migrate from v1.0.13 to v1.0.14 — `AstroResult.Closed` carries `(code, message)`

`AstroResult.Closed` changed from a `data object` to a `data class` that carries `code: String` and `message: String` describing **why** the SDK closed. Any `when (result)` branch over `AstroResult` must be updated.

`code` is a short machine-readable identifier in `UPPER_SNAKE_CASE`. `message` is a human-readable description. Both are plain strings — there is no enum, no whitelist, and no mapping. The SDK fixes the values it emits itself (see below) and may add new `code` values for in-SDK close paths in future releases without breaking the API.

## Before

```kotlin
AstroConnectView(
    configuration = configuration,
    onResult = { result ->
        when (result) {
            is AstroResult.Success -> { /* ... */ }
            is AstroResult.Closed -> analytics.log("sdk_closed")     // no payload
            is AstroResult.Failure -> { /* ... */ }
            is AstroResult.Event -> { /* ... */ }
        }
    },
)
```

## After

```kotlin
AstroConnectView(
    configuration = configuration,
    onResult = { result ->
        when (result) {
            is AstroResult.Success -> { /* ... */ }
            is AstroResult.Closed ->
                analytics.log("sdk_closed", mapOf("code" to result.code, "message" to result.message))
            is AstroResult.Failure -> { /* ... */ }
            is AstroResult.Event -> { /* ... */ }
        }
    },
)
```

> **Note:** `result === AstroResult.Closed` no longer compiles, because `Closed` is no longer a singleton. Use `is AstroResult.Closed` and read `result.code` / `result.message` instead.

## Codes emitted by the SDK itself

The following close codes originate in native code and emit fixed values:

| code | source | message |
|---|---|---|
| `CLOSED_BY_USER_HEADER_BUTTON` | User tapped the built-in header close button | `User tapped the close button` |
| `CLOSED_BY_HOST_APP` | You called `AstroConnectController.close()` | `Closed by host integrator` |
| `CLOSED_BY_SYSTEM_DISMISS` | SDK view was dismissed without an explicit close call (system back-press, sheet swipe-down, navigation back-swipe, host removal) | `View was dismissed` |
| `UNKNOWN` | Fallback when the close payload is missing or malformed | `` (empty string) |

Additional codes (for example `CLOSED_BY_USER_NAVIGATED_BACK`, `CLOSED_BY_USER_SIGNED_OUT`, `CLOSED_BY_USER_CANCELLED_PIN`, `CLOSED_BY_USER_DISMISSED_ERROR`) are emitted by SDK flows. They all follow the `CLOSED_BY_*` `UPPER_SNAKE_CASE` convention. The list is not exhaustive and may grow in future releases; treat any unrecognized `code` as a generic close.

## Other affected APIs

- `AstroConnectController.close()` takes no arguments. The SDK emits `Closed(code = "CLOSED_BY_HOST_APP", message = "Closed by host integrator")` for every call.
- The `AstroResult.onClosed { }` helper block now receives `(code, message)`.

### Before

```kotlin
result.onClosed { analytics.log("sdk_closed") }
```

### After

```kotlin
result.onClosed { code, message ->
    analytics.log("sdk_closed", mapOf("code" to code, "message" to message))
}
```

## Also in this release — `showCloseButton` and `autoSize` removed

The previously deprecated `AstroConfiguration` parameters `showCloseButton` / `autoSize` and the matching `Builder` setters `setShowCloseButton` / `setAutoSize` have been removed entirely. All four were deprecated in v1.0.11 with `@Deprecated(..., ReplaceWith("showHeader"))` and replaced by `showHeader` / `Builder.setShowHeader`. Any code that still references them will fail to compile.

There is no behavioral change beyond the removal: `showHeader` continues to control header visibility exactly as it did in v1.0.13.

### Before

```kotlin
val configuration = AstroConfiguration.builder()
    .setEnvironment("sandbox")
    .setAppIssuer("your-app-issuer")
    .setClientId("your-client-id")
    .setPartnerUserId("user-123")
    .setAccessToken("...")
    .setShowCloseButton(false)   // removed
    .setAutoSize(true)           // removed
    .build()
```

### After

```kotlin
val configuration = AstroConfiguration.builder()
    .setEnvironment("sandbox")
    .setAppIssuer("your-app-issuer")
    .setClientId("your-client-id")
    .setPartnerUserId("user-123")
    .setAccessToken("...")
    .setShowHeader(false)        // replaces both
    .build()
```

If you construct `AstroConfiguration(...)` directly instead of via the `Builder`, drop the `showCloseButton = ...` / `autoSize = ...` named arguments and pass `showHeader = ...` instead.

### Mapping

| Removed | Replace with |
|---|---|
| `AstroConfiguration.showCloseButton: Boolean?` | `AstroConfiguration.showHeader: Boolean?` |
| `AstroConfiguration.autoSize: Boolean?` | `AstroConfiguration.showHeader: Boolean?` |
| `AstroConfiguration.Builder.setShowCloseButton(Boolean?)` | `AstroConfiguration.Builder.setShowHeader(Boolean?)` |
| `AstroConfiguration.Builder.setAutoSize(Boolean?)` | `AstroConfiguration.Builder.setShowHeader(Boolean?)` |

`showHeader` defaults to `true` (the header bar with close button and co-branded logo is shown). Pass `showHeader = false` to hide the entire header bar — for example, when you render your own header and dismiss the SDK via `AstroConnectController.close()`.

### Caller-facing impact

- Any call site that still references `showCloseButton`, `autoSize`, `setShowCloseButton`, or `setAutoSize` will produce a compile error. Remove the call and, if header visibility was being toggled, switch to `showHeader` / `Builder.setShowHeader` with the equivalent value.
- The properties `AstroConfiguration.showCloseButton` and `AstroConfiguration.autoSize` are no longer readable. Read `AstroConfiguration.showHeader` instead.
